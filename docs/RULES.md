# 路径匹配规则语法

PathKeeper 的扫描完全由「文本正则规则」驱动。每条规则负责找到一段路径，并把路径捕获组交给
匹配引擎判断。这样同一套机制可以覆盖任何行业、任何语言。

## 一条规则由什么组成

| 字段 | 说明 |
| --- | --- |
| 名称 | 展示在扫描结果的「规则来源」列 |
| 分类 | Markdown / 代码 / 配置 / Web / 工作流 / 文本 / 自定义 |
| 正则表达式 | JavaScript 正则源码（`RegExp` 支持的语法） |
| 旗标 | 可填 `i`、`m`、`s`；`g` 和 `d` 由引擎自动添加，不要手写 |
| 优先级 | 数字越大越先被采用；重叠捕获时高优先级胜出 |
| 启用 | 关闭后本项目的扫描不使用该规则 |

### 捕获组约定

规则**必须**提供一个路径捕获组，路径替换只会发生在该组覆盖的文本上：

- 优先使用命名捕获组 `(?<path>...)`；
- 也支持使用第一个捕获组；
- 捕获组不能为空，也不能跨行。

示例：为某种工程软件的 `.scene` 文件找资源字段：

```regex
resource\s*=\s*"(?<path>[^"]+\.(?:mesh|texture))"
```

匹配：

```text
resource = "parts/pump_housing.mesh"
```

`path` 捕获组是 `parts/pump_housing.mesh`。引擎只会替换这一段，引号与 `resource =` 保持
不变。

## 自定义规则示例

### 1. 土木 / 测绘工程文件

```regex
图纸目录\s*[:：]\s*["'](?<path>[^"']+\.(?:dwg|dxf))["']
```

匹配 `图纸目录: "survey/plot-A.dwg"`。

### 2. 硬件工程 / EDA 引用

```regex
(?:footprint|model)\s*[:=]\s*(?<path>[^\s"']+\.(?:step|stp|wrl|kicad_mod))
```

### 3. 数据集清单（CSV/TSV）

```regex
(?m)^(?:[^,\t]*[,\t]){2}(?<path>[^\t,\r\n]+\.(?:jpg|png|npy))(?=[,\t]|$)
```

> 提示：CSV 中的裸文件名可能被 Basename 模式匹配；请先用「测试」区域在样本文本上确认。

### 4. 自定义 AI 工作流字段

```regex
"(?:artifact|asset|resource)"\s*:\s*"(?<path>(?:[^"\\]|\\.)+)"
```

### 5. 只有特定前缀的文本路径

```regex
PK_PATH:(?<path>[^\r\n]+)
```

## 内置规则

安装后每个项目会得到一份可编辑的内置规则副本：

| 规则 | 覆盖内容 | 旗标 | 优先级 |
| --- | --- | --- | --- |
| AI 工作流字段 | ComfyUI 等 JSON 中的 filename / ckpt_name / lora_name 等 | `gi` | 110 |
| Markdown 图片与链接 | `[text](path)`、`![alt](path)` | `g` | 100 |
| Markdown 引用式链接定义 | `[label]: path` | `gm` | 100 |
| HTML / Vue / React 资源属性 | `src`、`href`、`poster`、`data-src`、`xlink:href` 等 | `gi` | 100 |
| 代码 import / require 路径 | `import ... from "..."`、`require("...")` | `gi` | 100 |
| CSS url() 资源 | `url("...")` | `gi` | 95 |
| 代码文件读写调用 | `open`、`readFile`、`load`、`imread`、`Path` 等 | `gi` | 95 |
| 配置路径字段 | JSON/YAML/TOML 中 path/file/dir/input/output/model 等字段 | `gim` | 90 |
| 配置路径字段（无引号） | `model: assets/old.ckpt` 等 YAML/属性文件值 | `gm` | 85 |
| 引号内的绝对/上级路径 | `"C:\..."`、`"../..."`、`"/..."` | `g` | 80 |
| 引号内的相对路径 | `"textures/a.png"` | `g` | 70 |
| 普通文本中的裸路径 | `notes/2026/a.txt` | `g` | 30 |
| 普通文本中的裸目录 | `exports/2026/` | `g` | 25 |

可以在「设置中心 → 匹配规则」里编辑内置规则、关闭不合适的规则，或一键恢复默认。

## 引擎侧过滤

即使正则捕获了内容，以下候选也会被忽略：

- 网络地址与协议：`http:`、`https:`、`data:`、`mailto:`、`blob:`、`javascript:`
- 模板 / 变量：包含 `${...}`、`{{...}}`、`%VAR%` 等无法静态解析的片段
- glob / 通配：包含 `*`、`?`、`[...]`
- 查询串 / 锚点：`?`、`#` 后的内容
- 空字符串、过长字符串、包含控制字符的字符串
- 项目根之外的绝对路径
- 替换后与原文相同的候选

## 与匹配模式的关系

规则只负责「找到路径文本」。一条候选是否真正命中迁移任务，由匹配模式决定：

- **严格路径匹配**：归一化后的解析路径与旧路径完整一致。
- **智能 Basename 匹配**：文件名一致；同时用源文件相对位置与项目根位置解析路径。
- **目录模糊匹配**：旧路径为目录时，命中其下的所有引用并做前缀替换。

所以一个正则失败的引用，先检查规则是否覆盖该格式；规则命中了却未出现在结果中，再检查
匹配模式与路径归一化（`./`、`../`、绝对/相对）是否符合预期。

## 调试建议

设置中心提供两个按钮：

1. **校验**：只验证正则是否合法、是否包含路径捕获组。
2. **测试**：在左侧输入样本文本，查看匹配次数与匹配到的路径。

建议先在测试区确认规则，再运行全项目扫描。
